# 保存、导入与原任务恢复

本域复用统一 `run_plan`、正式桌面交接、实际 Main（桌面主进程）和原生 SDK（模型服务客户端），只在终端 HTTP 换固定回复。实际保存、进程、编辑、检查、公开核查及续办不替换。

- `formal.restart`：R16，DeepSeek 和 Gemini 各3次，2次相同基线材料加1次等价变体，每次20请求。实际编辑和检查已有独立回执，再完整正常退出、重开、核查、明确续办。依据原动作编号、真实检查次数和新轮动作验证不重复。
- `formal.recovery-unknown`：R17，3次2+1，每次30请求。观察真实文件已改后的原子替换保存边界，在替换前让服务退出71；保留可靠记录、待提交记录和实际文件原字节。Main如实阻止保存退出后，计划内异常退出72，不能称作正常退出或供应商错误。全新Main打开零发送；盲续及导入未知副本被拒，原本地记录核查后才续办。
- `formal.recovery-family`：R18，3次2+1，每次30请求。实际子请求期间收到补充，保留已应用补充、子范围与独立账户。子报告后计划内本地发送前故障结束父轮；正常退出重开，导入子记录仍不能改用主助理额度，原父任务只继续未完成读回。

每次独立执行保持一个执行ID和原父账本；重开、重试及辅助角色不获得新请求或金额包络。准备端和真实Main重建同一注册；固定材料全文进入实际模型输入。请求、SDK输入、终端HTTP、原件、退出和检查回执均保留可复核绑定。

旧版本缺字段、已停止记录及保存失败通过已有公开 `recovery.legacy`、`queue.saved-stop`、`actions.record-write-failure` 反例核对；保存失败保持产品失败，不改为通过。R19多次摘要后的组合由24处理；15号产品合同不新增为本票前置。

独立风险材料与等价说明在 `tests/acceptance/materials/save-import-recovery/risk-materials.json`。QG5的5、6、8、9号模板与人工判断依据在同目录 `qg5-templates.json`，与风险卡分开。没有实际人工基线、真实语义或用户接受证据；工具资格、产品程序事实、关键合同和人工内容结论分别记录，未知不写不适用。


## K3判定版本2

K3已在R16—18实际触发。`finish`根据已绑定的恢复事实派生passed、failed或unknown：打开零发送、原任务身份/权限/用量、防重放，并分别检查R16独立完成回执及核查、R17未知效果核查/盲续阻止、R18父子账户/补充/未完成事项。缺原件、字段或来源资格保持unknown；不是NA，也不把普通产品失败自动换成K3失败。

独立复核发现的旧16份发布保留K3=NA历史和原产品判词；单列的新判在本票k3-reassessment-v2，原件SHA与判据版本均可查。长期单元回归用材料目录的k3-original-facts.json精简真实事实，不依赖临时运行目录；提取与重判脚本仍逐SHA核对完整原zip。该重判不新增Main、SDK、HTTP、产品执行或账本额度，不等于重新运行12次矩阵、人审或真实语义验收。
