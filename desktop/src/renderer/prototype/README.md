# Myrk 前端布局原型

本目录为可丢弃的设计原型，不是正式客户端实现。目标：在同一根页面，通过 `?variant=A|B|C` 比较三种结构不同的布局。

## 设计依据

用户于 2026-11-10 确认：

- 回答、当前进度与待处理事项优先，技术记录按需展开。
- 白色、浅灰为主，少量强调色。
- 中文字号与控件清晰适中，不追求高密度。
- 在现有能力上整理页面，先比较主会话和输入区，再统一设置。

## 启动

在本工作区的 `desktop` 目录执行 `npm run prototype`。它只启动 Vite，复用共同项目根目录已有的 `desktop/node_modules`，不安装依赖、不启动 Electron 或 Python。

打开 http://127.0.0.1:5178/?prototype=frontend&variant=A 。底部工具条切换 A/B/C 与示例场景，也支持左右方向键；输入框、下拉框和设置弹窗中的方向键由当前控件处理。

- **A 对话优先**：左侧会话、主对话，当前工作和批准动作靠近输入框。
- **B 并排工作台**：窄功能栏、会话列表、对话与右侧进展；窄窗口将进展收为抽屉。
- **C 底部任务面板**：顶部会话标签、文档式对话、可展开的底部任务区。

场景：新会话、处理中、等待批准、已交付、中断恢复。设置演示保留回答服务、工作偏好、长期记忆、记录与导入四类。

## 数据与行为

数据在 `PrototypeContext.tsx` 内统一构造，三种布局使用相同内容。所有交互只更新内存；资料、文件夹、命令、服务地址和用量均为示例。密码框不读取或保存连接资料；复制、导入和文件打开只演示反馈，不访问系统资源。

原型入口要求 `import.meta.env.DEV` 且 URL 中含 `prototype=frontend`。正式路径仍加载原有 App；原型不挂载原有 App，也不连接 `window.myrk`。生产实现需依据用户选定方案重新整理并完成正式检查，不能把原型直接合入主分支。

缓存、临时目录和运行归属记录在共同项目根目录的 `.scratch/frontend-ui-prototype-20261110/runtime`，可用 `MYRK_PROTOTYPE_RESOURCE_ROOT` 指定另一个项目内专用目录。服务只监听 `127.0.0.1:5178`，停止命令为 Ctrl+C。

## 本轮验证

浏览器中查看三版；执行示例批准、排队、停止、继续、验收；切换五种场景与模型；查看四类设置；在 800×600 检查输入区、进展抽屉和批准入口；未见浏览器错误，未发现根页面水平溢出。

没有为可丢弃原型编写测试，也没有请求真实模型、运行项目工具或改写正式会话。

## 用户选择

用户于 2026-11-10 明确回复「A」，选择 A「对话优先」：左侧会话导航，中央对话，当前进度和待批准事项靠近输入区。浅色中性、适中密度与详情按需展开沿用先前确认。

此选择确定正式页面的布局方向；原型的示例数据和模拟动作不进入正式客户端。完整三版保留在原型分支，供后续实施回查设计依据。
